# Run the flutter maintenance pipeline

Execute the bundled bash script from the project root and let it handle the full sequence.

## Workflow

1. Confirm that the workspace looks like a Flutter project by checking for `pubspec.yaml`.
2. Run `scripts/run_flutter_pipeline.sh` against the project root.
3. Do not replace the bundled sequence unless the user explicitly asks for a custom flow.
4. Do not run `flutter run`.
5. Do not run `dart run build_runner watch`.
6. After execution, follow the output contract below exactly.

## Command sequence

The script already runs this sequence in order:

1. `flutter clean`
2. `flutter pub get`
3. `flutter pub upgrade`
4. `dart run build_runner clean`
5. `dart run build_runner build --delete-conflicting-outputs`
6. Validate `lib/gen/assets.gen.dart`
7. Validate that at least one `*.g.dart` file exists under `lib/` or `test/`

## Output contract

- If the script succeeds, return exactly `✅ Success`.
- If the script fails, return only the markdown error report generated by the script.
- Do not add introductions, explanations, or extra bullets before or after the required output.

## Execution notes

- Prefer running the script from the repository root: `bash <skill-path>/scripts/run_flutter_pipeline.sh "$PWD"`.
- If the current directory is not the project root, switch to the directory that contains `pubspec.yaml` first.
- Treat command-not-found, version-solving, syntax, builder, and missing-generated-file problems as failures.
- The script writes logs and reports under `.flutter_pipeline_reports/` in the target project only when there is a failure.
- If the full sequence succeeds, the script removes `.flutter_pipeline_reports/` before returning `✅ Success`.

## Reusable resource

- For Gemini CLI and Claude Code usage patterns, consult `references/agent-integration.md`.
- Use `scripts/run_flutter_pipeline.sh` as the single execution entrypoint.
